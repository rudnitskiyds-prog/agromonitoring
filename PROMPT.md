# Промпты для Claude Code — «Агромониторинг»

## Подготовка

1. Создайте пустую папку проекта и положите в неё:
   - `CLAUDE.md` в корень;
   - пять файлов агентов в `.claude/agents/`: `data-engineer.md`, `finance-modeler.md`,
     `ui-designer.md`, `copywriter.md`, `qa-reviewer.md`.
2. Запустите Claude Code в этой папке и выполните `/agents` — все пять агентов должны быть в списке.
3. Вставляйте промпты ниже по одному. Основная сессия — оркестратор: она раздаёт задачи агентам.

---

## Промпт 0 — запуск и план

```
Прочитай CLAUDE.md — это ТЗ сайта «Агромониторинг». Ты оркестратор команды из раздела 12,
агенты лежат в .claude/agents/. Код пока не пиши. Дай:
1) план по этапам 1–7 ниже: какие задачи какому агенту, что идёт параллельно, что последовательно;
2) вопросы по пробелам в ТЗ;
3) проверку окружения: node, npm, python, pandas, playwright; доступ к api.open-meteo.com,
   archive-api.open-meteo.com, rosstat.gov.ru, cbr.ru (curl -I на каждый).
Жди подтверждения.
```

## Этап 1 — каркас и контракты (оркестратор сам)

```
Этап 1. Сам, без агентов: создай проект по разделам 9–10 (Vite + React + TS + Tailwind + Recharts
+ lucide-react + vitest + Playwright), HashRouter, 8 страниц-заглушек, git init.
Затем src/types.ts — контракты между агентами: формат JSON данных, профиль хозяйства,
сигнатуры функций finance.ts, signals.ts, seasonality.ts, weather.ts (реализации — заглушки).
Покажи types.ts. Это основа для параллельной работы, поэтому согласуй его со мной.
```

## Этап 2 — фундамент (4 агента параллельно)

```
Этап 2. Запусти параллельно четыре субагента, каждому — задачу из его зоны:
- data-engineer: scripts/build_demo_data.py, fetch_weather.py, parse_rosstat.py (заготовка),
  JSON в public/data, src/lib/weather.ts (Open-Meteo из браузера + фолбэк), regions.ts.
- finance-modeler: finance.ts, signals.ts, seasonality.ts, store/farm.ts с демо-хозяйством
  (1 200 га, Краснодарский край, пшеница + подсолнечник) и тестами vitest.
- ui-designer: дизайн-система по разделу 8 и страница /#styleguide (токены, шрифты, кнопки,
  бейджи «Демо-данные» и «Допущение», карточка фактора, рамка графика), шапка и мобильное меню.
- copywriter: src/content/texts.ts для всех 8 страниц и онбординга.
Все работают по контрактам из types.ts. Когда все закончат, сведи отчёты, запусти сборку и тесты,
закоммить и покажи мне скриншоты styleguide.
```

## Проверка после каждого этапа

```
Запусти qa-reviewer на результат этапа. Найденное раздай агентам-владельцам
(параллельно, если файлы не пересекаются), потом пусть qa-reviewer перепроверит только исправленное.
Покажи итоговую таблицу проблем.
```

## Этап 3 — главная и онбординг

```
Этап 3. ui-designer: страницы «Главная» и «Моё хозяйство» по разделам 4 и 8 — тезис
«Рынок изменился — вот сколько это стоит лично вам», живая карточка расчёта демо-хозяйства,
полоса сезона, онбординг в 3 шага с допущениями и кнопкой «Пропустить — показать на примере».
Параллельно copywriter дорабатывает тексты этих страниц по ходу вёрстки.
Затем — проверка qa-reviewer.
```

## Этап 4 — аналитические страницы (параллельно по страницам)

```
Этап 4. Страницы 3–8 из раздела 4. Раздели работу так, чтобы файлы не пересекались:
- ui-designer №1: «Мой бизнес сегодня» и «Что если»;
- ui-designer №2: «Рынок и сезонность» и «Урожай и погода»;
- ui-designer №3: «Почему изменилась прибыль» (водопад + drill-down + хлебные крошки) и «Источники и методика».
Общие компоненты (ChartFrame, FactorCard и т. п.) делает только №1 — остальные ждут или используют готовые.
Если не хватает функции в lib — задача finance-modeler, а не правка ui-designer'ом.
Затем — проверка qa-reviewer.
```

## Этап 5 — сценарии

```
Этап 5. qa-reviewer: пройди сценарии С1–С3 из раздела 5 в Playwright, для каждого —
таблица «шаг → что видит пользователь → проблема». Раздай исправления владельцам,
перепроверь.
```

## Этап 6 — полировка

```
Этап 6. Параллельно:
```

## Доп. промпты

- **Выглядит шаблонно:** «ui-designer: страница X похожа на типовую админку. Перечитай раздел 8,
  предложи 2 варианта переработки со скриншотами, потом сделай выбранный».
- **Подмена данных:** «data-engineer: в raw/ лежит выгрузка Росстата <файл>. Разбери структуру,
  допиши parse_rosstat.py, замени демо-ряд реальным, сними флаг demo».
- **Новый регион:** «data-engineer: добавь <регион> в regions.ts и данные к нему».
- **Откат:** «Откати последний этап к рабочему коммиту и объясни, что сломалось».

## Если агенты конфликтуют или расходуют много токенов

- Конфликт правок: «Остановись. Покажи, какие файлы правили несколько агентов, и восстанови
  зоны из раздела 12».
- Экономия: запускайте параллельно не больше 2–3 агентов; qa-reviewer и copywriter можно
  перевести на `model: haiku` в их файлах.

## Что сделать вручную

1. fedstat.ru (ЕМИСС): средние цены производителей сельхозпродукции по регионам (месяц);
   посевные площади, валовые сборы, урожайность по регионам (год) → `raw/`.
2. Росстат: еженедельный мониторинг цен на нефтепродукты (дизель по субъектам) → `raw/`.
3. cbr.ru: история ключевой ставки → `raw/`.
