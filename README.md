# Агромониторинг

**Рынок изменился — вот сколько это стоит лично вам.**

Сайт для руководителя или экономиста растениеводческого хозяйства (500–5 000 га). Фермер один раз описывает хозяйство
(регион, культуры, площадь, затраты) и дальше видит не «рынок вообще», а как цена продукции, солярка, урожайность
и погода меняют себестоимость тонны, маржу на гектар и прибыль хозяйства в рублях. Конкурсный кейс «Аналитический сервис „Агромониторинг“».

Регионы: Краснодарский край, Саратовская область. Культуры: пшеница, ячмень, подсолнечник, кукуруза на зерно.

## Страницы

| # | Страница | Вопрос |
|---|---|---|
| 1 | Главная | Что это и зачем мне? |
| 2 | Моё хозяйство | Как описать себя? (форма в 3 шага, можно пропустить и взять демо-хозяйство) |
| 3 | Мой бизнес сегодня | Как рынок повлиял на меня? |
| 4 | Рынок и сезонность | Выгодно ли продавать сейчас? |
| 5 | Урожай и погода | Чего ждать от урожая? |
| 6 | Что если | Что будет, если цена, урожайность или солярка изменятся на ±30%? |
| 7 | Почему изменилась прибыль | Из-за чего? Водопад вкладов, drill-down |
| 8 | Источники и методика | Можно ли этому верить? |

### Сценарии

- **С1 «Утро понедельника».** Повторный визит открывает «Мой бизнес сегодня» с итогом в рублях, клик по карточке «Солярка» ведёт к недельному графику и пересчёту на тонну.
- **С2 «Продавать сейчас или ждать?».** «Рынок и сезонность»: текущая цена против сезонной нормы, вывод про окно продаж, переход в «Что если» с подставленной ценой.
- **С3 «Почему в этом году хуже?».** «Почему изменилась прибыль»: сезон 2026 против 2025, водопад вкладов, клик по «Урожайности», сравнение региона с соседним и РФ, погода сезона. В демо сюжет построен на **саратовском подсолнечнике и сухом августе 2026** (осадки в августе 12 мм при норме 34 мм по реальным данным ERA5).

## Запуск

Нужен Node 22+.

```bash
npm ci                              # зависимости
npm run dev                         # разработка, http://localhost:5173
npm test                            # unit-тесты (vitest): финансы, сигналы, сезонность, погода
npx playwright install chromium     # один раз, для e2e
npm run e2e                         # сценарии С1–С3 и смоук, 1440 и 375 px
npm run build                       # tsc + vite build -> dist/
npm run preview                     # проверить сборку локально
```

## Данные

Каждая цифра на сайте показывается с источником и датой. Формат файла `public/data/{indicator}_{region}[_{crop}]_{frequency}.json`:

```json
{ "indicator": "producer_price", "region": "krasnodar", "crop": "wheat", "unit": "руб./т",
  "source": "...", "source_url": "...", "updated_at": "2026-10-01", "frequency": "month",
  "demo": true, "series": [{ "date": "2026-10-01", "value": 17590 }], "note": "..." }
```

`date` — всегда `YYYY-MM-DD` (неделя — понедельник, месяц — первое число, год — 1 января). `demo: true` включает на сайте бейдж «Демо-данные».

| Ряд | Единица | Статус | Источник |
|---|---|---|---|
| Ключевая ставка (даты изменения) | % | **реальный** | Банк России, cbr.ru |
| Погода: температура, осадки, активные температуры, сухие дни (по месяцам, с 2019) | °C, мм, дни | **реальный** | Open-Meteo, архив ERA5, CC BY 4.0 |
| Прогноз погоды на 16 дней | °C, мм | **реальный**, в браузере; при ошибке — кэш `weather_*.json` | Open-Meteo, CC BY 4.0 |
| Цены производителей по культурам и регионам | руб./т | демо | Росстат / ЕМИСС |
| Цена дизтоплива по неделям | руб./л | демо | Росстат, мониторинг нефтепродуктов |
| Урожайность, посевная площадь, валовой сбор | ц/га, тыс. га, тыс. т | демо | Росстат / ЕМИСС |

Росстат и ЕМИСС из среды разработки недоступны, поэтому статистика не выдумывалась: демо-ряды синтетические, с правдоподобными уровнями и сезонностью, детерминированные (`scripts/build_demo_data.py`). Урожайность 2026 в демо согласована с реальной погодой ERA5, но сама урожайность остаётся демо.

## Как заменить демо-данные реальными

Python: `python3 -m venv .venv && .venv/bin/pip install -r scripts/requirements.txt`.

1. На [fedstat.ru](https://www.fedstat.ru/) найдите показатель (цена производителей, урожайность, посевная площадь, валовой сбор), «Выгрузить» в CSV или XLSX, положите файл в `raw/`. Дизтопливо — еженедельный мониторинг цен на нефтепродукты на rosstat.gov.ru.
2. Разберите выгрузку (пример для цены пшеницы в Краснодарском крае):
   ```bash
   .venv/bin/python scripts/parse_rosstat.py raw/price_wheat_krasnodar.xlsx \
     --indicator producer_price --region krasnodar --crop wheat --frequency month \
     --date-col "Период" --value-col "Значение" --filter "Регион=Краснодарский край"
   ```
   Скрипт перезапишет демо-файл реальным с `demo: false` и пересоберёт `public/data/index.json`. Подробности и форматы дат — в docstring `scripts/parse_rosstat.py`; проверка парсера: `--self-test`. Повторите для каждого ряда (4 культуры × 2 региона для цены, урожайности, площади, сбора; урожайность `--region russia` для сравнения).
3. Обновить ставку ЦБ и погоду: `.venv/bin/python scripts/fetch_key_rate.py`, `.venv/bin/python scripts/fetch_weather.py`.
4. Проверить формат: `.venv/bin/python scripts/validate_data.py`.
5. `build_demo_data.py` не перезаписывает файлы с `demo: false`, его можно запускать повторно для оставшихся демо-рядов.
6. После замены перепроверьте тесты: `e2e/scenarios.spec.ts` содержит ожидаемые суммы в рублях, посчитанные на демо-данных, их придётся обновить. Также проверьте вывод про сезонность и сюжет С3 — они зависят от цифр.

## Новый регион

1. Одна запись в `REGIONS` в `src/config/regions.ts`: название, координаты зерновой зоны, timezone, `compareWith`, культуры, календарь сезона, `defaultCosts`.
2. Данные: ряды `{indicator}_{regionId}[_{crop}]_{frequency}.json` для цены, дизеля, урожайности, площади, сбора; погода — `scripts/fetch_weather.py` читает координаты из `regions.ts` сам.
3. `scripts/validate_data.py` проверит формат и календарь сезона.
4. Для демо-рядов нового региона добавьте уровни в `scripts/build_demo_data.py`.

## Деплой на GitHub Pages

Сборка собирается с `base: './'` и `HashRouter`, ряды данных грузятся через `import.meta.env.BASE_URL`, поэтому сайт работает в любом подкаталоге (`/agromonitoring/`).

1. Запушьте проект в репозиторий GitHub (ветка `main`).
2. В репозитории: Settings → Pages → Source: **GitHub Actions**.
3. Workflow `.github/workflows/deploy.yml` на каждый push в `main` (и вручную) запускает `npm ci`, `npm test`, `npm run build` и публикует `dist/`. Задача e2e запускается только вручную.

## Допущения и ограничения

- Затраты на гектар и плановая урожайность по умолчанию — **условные допущения**, не статистика; на сайте помечены бейджем «Допущение» и редактируются.
- Цены, дизель, урожайность, площадь и сбор — демо-ряды, пока не заменены выгрузками Росстата.
- Погода — одна точка в зерновой зоне региона (ERA5, сетка около 25 км), не средняя по региону. Последний месяц архива может быть неполным.
- Ключевая ставка — ряд изменений, действует до следующей точки.
- Профиль хозяйства хранится в `localStorage`; в приватном режиме живёт до перезагрузки.
- Календарь сезона типовой для зоны, ориентир, а не агрономическая рекомендация.
- Шрифты подключаются с Google Fonts; без сети подставляются запасные.
