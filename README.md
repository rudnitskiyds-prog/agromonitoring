# Агромониторинг

**Рынок изменился — вот сколько это стоит лично вам.**

Сайт для руководителя или экономиста растениеводческого хозяйства (500–5 000 га). Фермер один раз описывает хозяйство
(регион, культуры, площадь, затраты) и дальше видит не «рынок вообще», а как цена продукции, солярка, урожайность
и погода меняют себестоимость тонны, маржу на гектар и прибыль хозяйства в рублях. Конкурсный кейс «Аналитический сервис „Агромониторинг“».

Регионы: Краснодарский край, Саратовская область. Культуры: пшеница, ячмень, подсолнечник, кукуруза на зерно.

## Страницы

| # | Страница | Вопрос |
|---|---|---|
| 1 | Главная | Что это и зачем мне? |
| 2 | Моё хозяйство | Как описать себя? (форма в 3 шага, можно пропустить и взять демо-хозяйство) |
| 3 | Мой бизнес сегодня | Как рынок повлиял на меня? |
| 4 | Рынок и сезонность | Выгодно ли продавать сейчас? |
| 5 | Урожай и погода | Чего ждать от урожая? |
| 6 | Что если | Что будет, если цена, урожайность или солярка изменятся на ±30%? |
| 7 | Почему изменилась прибыль | Из-за чего? Водопад вкладов, drill-down |
| 8 | Источники и методика | Можно ли этому верить? |

### Сценарии

- **С1 «Утро понедельника».** Повторный визит открывает «Мой бизнес сегодня» с итогом в рублях, клик по карточке «Солярка» ведёт к недельному графику и пересчёту на тонну.
- **С2 «Продавать сейчас или ждать?».** «Рынок и сезонность»: текущая цена против сезонной нормы, вывод про окно продаж, переход в «Что если» с подставленной ценой.
- **С3 «Почему в этом году хуже?».** «Почему изменилась прибыль»: сезон 2026 против 2025, водопад вкладов, клик по «Урожайности», сравнение региона с соседним и РФ, погода сезона. В демо сюжет построен на **саратовском подсолнечнике и сухом августе 2026** (осадки в августе 12 мм при норме 34 мм по реальным данным ERA5).

## Запуск

Нужен Node 22+.

```bash
npm ci                              # зависимости
npm run dev                         # разработка, http://localhost:5173
npm test                            # unit-тесты (vitest): финансы, сигналы, сезонность, погода
npx playwright install chromium     # один раз, для e2e
npm run e2e                         # сценарии С1–С3 и смоук, 1440 и 375 px
npm run build                       # tsc + vite build -> dist/
npm run preview                     # проверить сборку локально
```

## Данные

Каждая цифра на сайте показывается с источником и датой. Формат файла `public/data/{indicator}_{region}[_{crop}]_{frequency}.json`:

```json
{ "indicator": "producer_price", "region": "krasnodar", "crop": "wheat", "unit": "руб./т",
  "source": "...", "source_url": "...", "updated_at": "2026-10-01", "frequency": "month",
  "demo": true, "series": [{ "date": "2026-10-01", "value": 17590 }], "note": "..." }
```

`date` — всегда `YYYY-MM-DD` (неделя — понедельник, месяц — первое число, год — 1 января). `demo: true` включает на сайте бейдж «Демо-данные».

| Ряд | Единица | Статус | Источник |
|---|---|---|---|
| Цены производителей: Краснодарский край и Саратовская область, 4 культуры, с января 2021 | руб./т | **реальный** (отдельные месяцы пропущены, `null`) | Росстат: `cena_sx_MM-YYYY.xlsx` (с 2025) и ЕМИСС 57693 (2021–2024) |
| Цены производителей по РФ, 4 культуры, с января 2021 | руб./т | **реальный** (для сезонного профиля за 5 лет) | Росстат, `cena_sx_MM-YYYY.xlsx` |
| Цена дизтоплива по РФ, понедельно, с января 2022 | руб./л | **реальный**, среднее по России | Росстат, `nedel_sred_cen.xlsx` |
| Цена дизтоплива по субъектам и РФ, помесячно, с января 2021 | руб./л | **реальный** (недельных региональных данных нет) | Росстат, `sred_potreb_cen_*.xlsx` |
| Урожайность, валовой сбор, посевные площади: Краснодарский край, Саратовская область, 4 культуры, 2019–2024 (площади и сбор пшеницы, ячменя, кукурузы — по 2025) | ц/га, тыс. т, тыс. га | **реальный**; ряды заканчиваются на последнем опубликованном годе | ЕМИСС 31533, 30950, 31328; подсолнечник — также «Регионы России» 2025 |
| То же по РФ | ц/га, тыс. т, тыс. га | **реальный**, 2019–2024 (площади — по 2025) | Росстат: `uroj_.xls`, `val_.xls`, `posev_pl.xls` |
| Ключевая ставка (даты изменения) | % | **реальный** | Банк России, cbr.ru |
| Погода: температура, осадки, активные температуры, сухие дни (по месяцам, с 2019) | °C, мм, дни | **реальный** | Open-Meteo, архив ERA5, CC BY 4.0 |
| Прогноз погоды на 16 дней | °C, мм | **реальный**, в браузере; при ошибке — кэш `weather_*.json` | Open-Meteo, CC BY 4.0 |

Все ряды в `public/data` реальные (`demo: false`); демо-генератор `scripts/build_demo_data.py` остаётся для новых регионов, у которых
нет реальных данных, и не перезаписывает реальные файлы. Итоги 2025 года по урожайности Росстат ещё не опубликовал, 2026 — только весной 2027,
поэтому ряды не достраиваются. Для региона без собственного ряда дизеля сайт берёт `diesel_price_russia_week`
(в данных `region: "russia"` — интерфейс показывает «среднее по РФ»).

## Сборщик

`.venv/bin/python scripts/collect.py` скачивает с https://rosstat.gov.ru/statistics/price свежие `cena_sx_MM-YYYY.xlsx`
(имя меняется каждый месяц), `nedel_sred_cen.xlsx` и файлы потребительских цен `sred_potreb_cen_*.xlsx`; с rosstat.gov.ru/enterprise_economy —
`uroj_.xls`, `val_.xls`, `posev_pl.xls`; из ЕМИСС (fedstat.ru, JSON-эндпоинт сетки `/indicator/dataGrid.do`) — показатели 57693, 31533,
30950, 31328 (выгрузки сохраняются как `raw/emiss_<id>.json`); подсолнечник по субъектам дополняется сборником «Регионы России 2025»
(`raw/Region_Pokaz_2025.pdf`, разбор — `raw/regions_sunflower.csv`). Всё кладётся в `raw/` (старые файлы не удаляются), разбирается и пишется
в `public/data` с `demo: false`, затем пересобирается `index.json` и запускается `validate_data.py`. Адреса скачанных файлов
запоминаются в `raw/collect_meta.json` и попадают в `source_url` рядов; дата «Обновлено» из листа «Содержание» — в `updated_at`.
`--offline` разбирает уже лежащие в `raw/` файлы без сети и работает только после онлайн-запуска: тяжёлые выгрузки (`raw/*.xlsx`, `*.xls`, `*.pdf`) не хранятся в git, их скачивает сам сборщик. Субъекты берутся из `src/config/regions.ts` по названию региона.

**Сертификаты Минцифры.** Сайт Росстата отдаёт сертификат, выпущенный удостоверяющим центром Минцифры России, которого нет
в стандартных хранилищах. Цепочка лежит в `scripts/certs/russian_ca_bundle.pem` (Sub CA 2024, Sub CA 2022, Root) и подключается
явно к проверке TLS. Источник — официальные сертификаты Минцифры (Russian Trusted Root CA и промежуточные); перед использованием
сверьте отпечатки SHA-256:

| Сертификат | SHA-256 |
|---|---|
| Russian Trusted Root CA | `D2:6D:2D:02:31:B7:C3:9F:92:CC:73:85:12:BA:54:10:35:19:E4:40:5D:68:B5:BD:70:3E:97:88:CA:8E:CF:31` |
| Russian Trusted Sub CA (2022) | `BB:BD:E2:10:3E:79:0B:99:9E:C6:2B:D0:3C:F6:25:A5:A2:E7:C3:16:E1:0A:FE:6A:49:0E:ED:EA:D8:B3:FD:9B` |
| Russian Trusted Sub CA (2024) | `21:55:78:50:36:C9:00:DB:B5:F1:BB:2A:15:69:C8:0C:55:59:5B:D6:BF:94:86:7A:29:BB:DD:BC:7D:88:A3:F2` |

Проверку TLS **не отключаем** (`verify=False` и `curl -k` не используются): иначе подмена файла по дороге выглядела бы как
официальная статистика. Скачивание идёт через стандартный `urllib`/`ssl`, а не `requests`: `requests` на системном LibreSSL 2.8
(macOS) падает на разборе сертификата цепочки Минцифры, а `ssl` проверяет цепочку и имя хоста полностью.

## Как заменить или дополнить данные

Python: `python3 -m venv .venv && .venv/bin/pip install -r scripts/requirements.txt` (pandas, openpyxl, xlrd, pypdf).

1. Цены, дизель, урожайность, площади и сбор уже реальные (`scripts/collect.py`). Для нового региона или показателя вручную выгрузите нужное с [fedstat.ru](https://www.fedstat.ru/) в CSV или XLSX и положите файл в `raw/`.
2. Разберите выгрузку (пример для цены пшеницы в Краснодарском крае):
   ```bash
   .venv/bin/python scripts/parse_rosstat.py raw/price_wheat_krasnodar.xlsx \
     --indicator producer_price --region krasnodar --crop wheat --frequency month \
     --date-col "Период" --value-col "Значение" --filter "Регион=Краснодарский край"
   ```
   Скрипт перезапишет демо-файл реальным с `demo: false` и пересоберёт `public/data/index.json`. Подробности и форматы дат — в docstring `scripts/parse_rosstat.py`; проверка парсера: `--self-test`. Повторите для каждого ряда (4 культуры × 2 региона для урожайности, площади, сбора; урожайность `--region russia` для сравнения).
3. Обновить ставку ЦБ и погоду: `.venv/bin/python scripts/fetch_key_rate.py`, `.venv/bin/python scripts/fetch_weather.py`.
4. Проверить формат: `.venv/bin/python scripts/validate_data.py`.
5. `build_demo_data.py` не перезаписывает файлы с `demo: false`, его можно запускать повторно для оставшихся демо-рядов.
6. После замены перепроверьте тесты: `e2e/scenarios.spec.ts` содержит ожидаемые суммы в рублях, посчитанные на демо-данных, их придётся обновить. Также проверьте вывод про сезонность и сюжет С3 — они зависят от цифр.

## Новый регион

1. Одна запись в `REGIONS` в `src/config/regions.ts`: название, координаты зерновой зоны, timezone, `compareWith`, культуры, календарь сезона, `defaultCosts`.
2. Данные: ряды `{indicator}_{regionId}[_{crop}]_{frequency}.json` для цены, дизеля, урожайности, площади, сбора; погода — `scripts/fetch_weather.py` читает координаты из `regions.ts` сам.
3. `scripts/validate_data.py` проверит формат и календарь сезона.
4. Для демо-рядов нового региона добавьте уровни в `scripts/build_demo_data.py`.

## Деплой на GitHub Pages

Сборка собирается с `base: './'` и `HashRouter`, ряды данных грузятся через `import.meta.env.BASE_URL`, поэтому сайт работает в любом подкаталоге (`/agromonitoring/`).

1. Запушьте проект в репозиторий GitHub (ветка `main`).
2. В репозитории: Settings → Pages → Source: **GitHub Actions**.
3. Workflow `.github/workflows/deploy.yml` на каждый push в `main` (и вручную) запускает `npm ci`, `npm test`, `npm run build` и публикует `dist/`. Задача e2e запускается только вручную.

## Допущения и ограничения

- Затраты на гектар и плановая урожайность по умолчанию — **условные допущения**, не статистика; на сайте помечены бейджем «Допущение» и редактируются.
- Урожайность реальная за 2019–2024 гг.; итогов 2025–2026 у Росстата пока нет (площадь и сбор зерновых по регионам есть и за 2025). Ряды не достраиваются.
- Затраты по умолчанию — допущения, откалиброванные `scripts/calibrate_costs.py` по официальной статистике на базе 2024 г. (средняя цена производителей 2024 / (1 + рентабельность без субсидий по РФ, «Сельское хозяйство в России 2025», табл. 6.18) × средняя реальная урожайность региона 2022–2024; структура — табл. 6.2). Инфляция к 2026 г. не добавлена. Пользователь может их править.
- Цены производителей по регионам реальные только с января 2025 (в файле Росстата помесячные региональные таблицы есть только за 2025–2026), часть месяцев пропущена («...», «-»); сезонный профиль за 5 лет строится по ряду РФ. Дизель — среднее по России.
- Погода — одна точка в зерновой зоне региона (ERA5, сетка около 25 км), не средняя по региону. Последний месяц архива может быть неполным.
- Ключевая ставка — ряд изменений, действует до следующей точки.
- Профиль хозяйства хранится в `localStorage`; в приватном режиме живёт до перезагрузки.
- Календарь сезона типовой для зоны, ориентир, а не агрономическая рекомендация.
- Шрифты подключаются с Google Fonts; без сети подставляются запасные.
